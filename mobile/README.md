# PhonicsFriends — mobile

A Flutter app that teaches English phonics to young children, built against a
FastAPI backend in the same repository. The child side is designed to be
driven rather than browsed: the app opens on whatever comes next and resumes
exactly where the last session stopped, because a five-year-old choosing
between four activities is being handed a planning problem before the lesson
has started.

## Running it

```bash
flutter pub get
dart run build_runner build --delete-conflicting-outputs   # injectable + freezed + json_serializable
flutter run
```

The API base URL is chosen by build mode in `lib/core/constants/app_constants.dart`:
release builds use the deployed backend, debug builds a local one. Override it
without editing the file:

```bash
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:8000/api/v1
```

## Structure

```
lib/
  core/        cross-feature infrastructure
    audio/     phoneme playback with an on-disk cache, voice messages
    auth/      biometric unlock, the parent gate
    di/        get_it + injectable wiring
    network/   Dio client, interceptors, failure mapping
    router/    go_router configuration and redirects
    session/   the learning cursor — what the child does next
    theme/     colours, spacing, typography
  features/    one folder per feature, each split data / domain / presentation
```

Each feature owns its own `data` (models, remote data sources), `domain`
(entities) and `presentation` (Cubit, screens, widgets) layers. State is
`flutter_bloc` Cubits with `equatable` states; navigation is `go_router`;
dependencies are resolved through `get_it` and generated by `injectable`.

## Tests

```bash
flutter test
```

Two kinds live side by side. Ordinary unit and widget tests cover the parts
where a mistake is silent — the learning cursor, day planning, grapheme
handling, word alignment for pronunciation scoring, and the API contract the
engagement models depend on.

The `*_preview_test.dart` files are golden tests that exist to be looked at.
They render a screen or widget into a PNG checked in beside the test, with the
app's real fonts loaded, so a UI change can be reviewed as an image rather
than as a diff of layout code:

```bash
flutter test --update-goldens test/lessons/journey_map_preview_test.dart
```

Without `test/support/preview_fonts.dart` the test binding substitutes a
placeholder face and every glyph renders as a filled box, which makes the
image useless for reviewing anything but gross layout.

## Platform notes

Portrait is forced at startup. Firebase is initialised in `main.dart`;
Android is configured (`android/app/google-services.json`), iOS still needs
its `GoogleService-Info.plist`. The parent dashboard is behind a device
biometric prompt, with an arithmetic question as the fallback gate — a child
who watches a PIN typed once knows it forever.
